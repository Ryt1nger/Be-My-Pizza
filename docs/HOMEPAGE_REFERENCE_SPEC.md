# Be My Pizza — спецификация мобильной главной по оригинальному макету

**Статус:** изучено, ещё не реализовано по этой спецификации · 21.11.2026  
**Основание:** оригинальный JPG `главная.jpg` из предоставленного владельцем `pizza.zip`; показан повторно 21.11.2026. Исходное разрешение изображения **823 × 1910 пикселей**. Все значения ниже ориентировочные: это растр без Figma/исходных координат. Проверять в браузере на ширине ~390–412 CSS px.

## Неприкосновенная композиция

Экран — непрерывная вертикальная композиция на почти белом кремовом фоне (сэмпл #FCF7F3). Сверху iOS status bar с Dynamic Island и индикаторами, затем **компактная шапка**, **главный герой с огромной пиццей справа**, **короткий промобаннер с фуд-композицией**, заголовок «Популярное», **две товарные карточки**, затем **плавающая закруглённая нижняя навигация** с iOS home indicator. Ни новых блоков, ни служебных плашек «черновик» внутри страницы!

В обычном React-приложении status bar / home indicator НЕ рисовать: их обеспечивает системный iOS или отдельная GitHub Pages iPhone-обёртка. Двойные острова, двойные нижние полоски и накладывающиеся панели запрещены.

## Пропорции и ритм

- Исходный JPG — 823 × 1910; при просмотре около 2× дизайнерского масштаба соответствует ширине ~412 CSS px, но это **НЕ точный экспорт Figma**.
- Левый/правый отступы большинства блоков — около 16–25 CSS px. Главная пицца справа выходит за сетку и частично за viewport.
- Hero визуально занимает большую долю первой прокрутки; крупный текст вплотную соседствует с фуд-фото, но не перекрывает читабельность.
- Промо сразу под hero (никаких лишних 100px пустоты); затем заметный, но умеренный отступ перед «Популярное».
- Верхний срез товарной карточки содержит фото почти во всю ширину, ниже компактная белая зона текста/цены.
- Нижняя навигация высотой около 75–95 CSS px с округлёнными верхними/всеми углами; должна оставаться видимой и не закрывать детали карточек при прокрутке.

## Шрифты, цвета, графика

- Фон кремовый: приблизительно `#FCF7F3` — подтверждён сэмплом растра.
- Основной тёмно-зелёный заголовков: приблизительно `#083123`; зелёный CTA и иконок: прибл. `#145421`; дополнительные блоки — насыщенный зелёный/градиент.
- Акцент оранжевый в лого и счётчике корзины; не превращать всю страницу в оранжевую.
- Основной шрифт визуально геометрический жирный sans с плотной посадкой и коротким межстрочьем; нельзя выдавать случайный system-font за точное совпадение. Сначала подобрать подходящую открытую гарнитуру, затем проверить визуально.
- Ранее владелец прислал **круглый официальный логотип** отдельно, но в **этом макете стоит иной формат — словесная версия Be My Pizza**. При вёрстке учитывать отличие: не заменять wordmark круглым значком автоматически.
- Владелец предоставил два **прозрачных PNG-спрайта оригинальных иконок** (тёмно-зелёный и чёрный, с оранжевым пламенем). Использовать именно их и подготовить индивидуальные прозрачные SVG/PNG/WebP ассеты с правильным соотношением сторон; **не заменять** значками `lucide-react`, если есть оригинальный эквивалент.

## Фото: причина некачественного текущего результата

В GitHub был закоммичен временный `apps/customer/public/media/catalog-preview.webp` ~4 КБ для **15** товаров; он автоматически масштабируется на большие hero/карточки через `ProductPhoto`, поэтому изображения становятся размытыми. Это техническая временная заглушка, категорически неприемлемая для согласования дизайна.

В подготовленном архиве `Be_My_Pizza_Labeled_Catalog.zip` присутствуют исходные высококачественные фото: `photos/pizza/02_Ветчина и бекон.jpg`, `04_Пепперони.jpg`, `06_Четыре сыра.jpg`, каждое **1254 × 1254 px**, плюс ещё 12 фотографий. Надо: взять **оригинальные файлы**, сделать индивидуальные оптимизированные версии (например WebP без заметной потери, отдельные responsive размеры), физически добавить `apps/customer/public/media/products/<slug>.webp`, проверить Network/изображения. Не масштабировать низкокачественный атлас, не использовать CSS как замену разрешения.

**Особенность:** стилизованные рекламные фотографии в макете отличаются кадрированием/содержимым от некоторых реальных карточных фото из архива; для полного pixel-match могут потребоваться отдельные исходники hero и баннерного коллажа. До их появления аккуратно использовать разрешённые оригинальные фото без выдумывания нового товара и без имитации «точного» совпадения.

## Что сейчас сделано неправильно (скриншот работающего приложения 21.11.2026)

1. Служебная зелёная плашка «Черновик…» между header и hero — отсутствует в макете и ломает вертикальную композицию. Удалить с самой страницы, пометку черновика оставить вне app (в демо-обёртке).
2. Круглый логотип вместо словесного — визуально другое решение.
3. Hero набран в **две** большие строки вместо обязательных **трёх** и имеет чрезмерно крупную замыленную пиццу на фоне серовато-бежевой капсулы.
4. Подзаголовок изменён: макет требует «Свежие ингредиенты, быстрая доставка в Орехово».
5. Баннер занимает слишком большую высоту, рекламный фотоколлаж отсутствует, текст и метка изменены.
6. Каталог показывает заметно размытые увеличенные превью. Главная — только после исправления фотографий.
7. Карточки опускаются ниже нижней навигации на показанном экране; в макете на первом кадре видны обе карточки, названия, характеристики и цены.
8. Нижняя навигация использует **не те значки** («Меню» сейчас приборы, нужно 4 кружка), нет нужного визуального решения плавающей капсулы.
9. Кнопка товара сейчас «стрелка вверх-вправо» вместо **круглого плюса**.
10. Отступы, плотность, типографика и радиусы должны соответствовать макету, а не свободной адаптации.

## Критерии приёмки первой главной

- Сравниваем **полный скриншот** при одинаковой ширине (ориентир 390–412px CSS) с оригиналом JPG, отдельно карточки/навбар/промо.
- **Никаких** заметно растянутых, замыленных или отсутствующих картинок. Сверить минимум три фото товаров 02/04/06 и кадрирование.
- Заголовки, основные строки, карточки, навигация и иконки соответствуют макету. Не добавлять несогласованных баннеров/меток.
- Все tappable элементы имеют реальные действия либо честно показывают состояние «ещё не реализовано». Не показывать фальшивые суммы, баллы, значок 2 товара, скидки/акции как реальные.
- Статус-бар и Dynamic Island рисуются **только в demo/iPhone wrapper** или ОС, не внутри React content. Нижняя навигация не перекрывает карточки при скролле.
- У владельца явное право утверждения. Нельзя маркировать страницу утверждённой без подтверждения.


## Корректировки по реальным скриншотам владельца (21.11.2026, 15:30–15:37)
- Скриншот **текущего** блока «Популярное» показывает много пустого пространства вокруг пицц, фото находится в узкой верхней части карточек, а цена слишком отдалена от описания.
- Целевой скриншот: пиццы практически доходят до краёв своих карточек, кроп крупнее; текст расположен компактно, цена ближе к характеристикам; фотография кажется естественной частью карточки, а не отдельной белой плашкой.

- Не подменять реальные фотографии вымышленными. Если оригинал фото не совпадает с фуд-фото на макете (другие ингредиенты/раскладка), обеспечить лучший кроп и честно отметить ограничение.
